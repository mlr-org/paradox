## Additional finding during implementation

Narrow floating-point grid axes can move backwards because the compatibility
quantile formula retains R's separate rounded operations. Adjacent-only axis
deduplication therefore emits duplicate rows and can spuriously exceed
`upper_limit`. Preserve the quantile arithmetic and earliest nominal levels;
detect decreases and use the native R matcher only for those axes. Measure
ordinary numeric grids to check the cost of the added comparison. Use the same
`Rf_match` API already used elsewhere in the package, not a new numeric hash
engine or a new old-R API exception. Matching the axis against itself gives
each value's first occurrence, including the existing signed-zero and missing
value semantics.

The wide-graph benchmark also identified a remaining repeated schema scan in
Design column mapping. Generated designs ordinarily keep schema order; compare
the corresponding IDs before entering the existing name search for reordered
columns. This avoids a second index allocation and preserves the full
encoding-aware name check. Add reversed-column tests/benchmarks as the control
for the additional comparison on the less common path.

The paired ordinary-axis benchmark exposed an approximately 4% cost for the
new decrease check on a 20,001-point numeric grid. Reviewing its equality
helper found three unnecessary out-of-line R missing-value checks for every
pair of unequal finite values. Use C99 `ISNAN` classification first and retain
`R_IsNA` only when both values are NaNs. This preserves NA/NaN, infinity, and
signed-zero semantics while removing ordinary-path calls; remeasure before
retaining it. The running full-suite snapshot is kept immutable and is not
interrupted or rebuilt underneath its workers.

The first full-suite launch did not reach a package test: its coordinator
loaded dependencies from `R_LIBS_USER`, but each child replaced that variable
with the candidate-only library. The production release driver supplies
`R_LIBS` explicitly, which hid this gap in the standalone installed-test
runner. Propagate the coordinator's effective ordered `.libPaths()` as the
worker's `R_LIBS`; extend the existing two-worker regression to repeat against
a candidate-only copy with dependencies supplied solely via `R_LIBS_USER`.
This fixes standalone reuse without rebuilding packages or weakening DSO
identity checks. The failed launch remains diagnostic evidence, not a test
failure or a passing full-suite result.

## Implemented design decisions

The capsule/R6 split, closed Domain/Condition engines, operation snapshots,
and ordinary-R ownership model already fit the project well. This review keeps
them. It adds no persistent cache, native resource, public API, serialization
schema, fallback engine, or downstream adaptation requirement.

- The shared dependency planner now uses outgoing edge links and a min-heap:
  ordering takes O(E + P log P), instead of repeated O(P squared + P E)
  scans. Its ordering priority remains schema position for Design and realized
  branch count/schema position for grids. FIFO ordering would not preserve the
  contract. Wide endpoint lookup reuses the existing encoding-aware ID index;
  the bounded small-graph path avoids building that index.
- Design column mapping checks the corresponding schema ID first. This makes
  the usual schema-ordered input linear without an additional index; explicitly
  reordered input retains the existing general name search. All name,
  dimension, ownership, and generation checks remain.
- Realized numeric axes retain the exact compatibility quantile formula. A
  decrease triggers native first-occurrence matching, compacting values and
  their nominal ranks together. Sorting values or replacing the quantile
  formula would change observable grid order or floating-point values. The
  equality helper calls R's NA classifier only for two NaNs, not for ordinary
  unequal numbers.
- Arbitrary R RNG callbacks remain R callbacks. Truncation discards unknown
  comparisons, fills one bounded output buffer when several batches are needed,
  and preserves valid-stream batch sizes, draw order, and final RNG state.
  The successful single-batch path does not allocate the extra buffer.
  Normal defaults rescale the subtraction only when its intermediate width
  overflows; ordinary finite arithmetic is unchanged.
- Parallel installed-test workers inherit the coordinator's effective ordered
  library search path. DSO identity verification, isolated homes, nested thread
  caps, and the exclusive ConfigSpace lane remain unchanged.

The graph speedup trades modest additional operation-local scratch for removal
of repeated scans. At 1,024 parameters, the profiler records about 55 KiB more
allocation for a dependent Design plan and 78 KiB more for a dependent grid.
Independent plans instead save about 9 KiB. No scratch survives the operation.
Rejection sampling reduces recorded allocation from 141,528 to 125,480 bytes
on the all-accepted case, and from 1,012,376 to 936,928 bytes at 3% acceptance.
These are `Rprofmem` observations, not complete C stack/small-arena accounting.

## Measurements and verification

snapshot comes from the starting Git commit above. Baseline and final packages
use the same local R 4.6.1, GCC 14.3 strict GNU C99 profile, and dependency
library. Incremental builds reuse only unchanged translation units within

The final benchmark uses `benchmarks/review-20260905.R`, CPU affinity 6,

These are bounded synthetic workload measurements, not claims about total
optimizer runtime. The fastest wide-plan measurements approach the timer's
resolution, so their speedups are deliberately approximate. The original
numeric-grid fix alone cost about 4%; the final missing-value-call cleanup
more than recovers that cost, ending about 10% faster than the baseline.

The short 1,024-axis independent-grid blocks initially suggested a 7% timing
regression, but each block contained only ten calls and was quantized to
milliseconds. A separate unchanged-code control uses seven blocks of 1,000
calls in both orders (`baseline-a9.tsv`, `final-f9.tsv`, `final-f10.tsv`,
`baseline-a10.tsv`, driven by the retained
`benchmark-singleton-grid.R`). Baseline medians are 876/870 microseconds and
final medians are 879/879 microseconds; the balanced baseline/final ratio is
0.9932. This bounds the apparent outlier to about 0.7%, not 7%, with unchanged
allocation. Common-path results are therefore essentially flat, not claimed
to be mathematically identical in timing.
