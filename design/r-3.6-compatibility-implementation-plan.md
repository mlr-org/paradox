## 1. Release contract

Paradox 2 will declare and support `R >= 3.6.0`.  The oldest routinely executed
runtime will be the final patch release, R 3.6.3, and the native header matrix
will compile against the R 3.6.0 minimum plus R 4.0.0 and 4.2.0 transition
headers. A patch-release accident cannot masquerade as support for the complete
3.6 series, and endpoint runtimes cannot hide an uncompiled intermediate API
combination.

This change must preserve the current Paradox-2 behavioral, ownership,
corruption-detection, ALTREP, serialization, and performance contracts.  Old R
is another implementation environment, not another semantic implementation:

- current R keeps its current public-API ordinary-frame fast paths, with one
  conservative rooting proof shared across supported API branches because
  hostile class metadata can allocate during facade admission, and
  recognized callback-backed user databases rejected before binding calls;
- version differences are centralized behind small native compatibility
  helpers or build-system selection;
- the graph walker may retain narrow capability gates for edges an old runtime
  cannot expose, but no semantic operation gains an old-R duplicate;
- no operation is replayed in R, through data.table, or through checkmate;
- no persistent cache, weakened validator, or old-R-only behavioral fallback
  is introduced.

The only possible non-public API use is a narrow, version-bounded operation
that has no public equivalent on the affected old releases and is necessary to
retain an existing supported contract.  Every such use must be declared by the
old headers, exported by the runtime, centralized in `src/r_api_compat.c`,
listed in `environment/r-api-exceptions.tsv`, absent from versions where a
public replacement exists, and covered by source-token, header, DSO, and
runtime tests.  Internal layout access, copied R internals, unregistered calls,
and private data.table APIs remain forbidden.

## 2. Audit before implementation

The audit will cover, independently:

1. `DESCRIPTION`, `NAMESPACE`, R syntax and base-R calls, imported dependency
   floors, testthat edition/tooling, serialization, and generated help;
2. every native identifier and header, ALTREP use, promise/binding inspection,
   attribute traversal, routine registration, protection discipline, integer
   conversion, and compiler-language feature;
3. `src/Makevars*`, the effective C standard and flags on R 3.6, Unix and
   Windows build behavior, strict GCC/Clang warnings, and CRAN portability
   guidance;
4. the API source/header audit, runtime matrix, direct native probes,
   sanitizer/memory harnesses, verification coordinator, CI, and their
   version-specific policies;
5. an actual clean install and focused test baseline on isolated R 3.6.3,
   recorded before compatibility edits where the package metadata permits it.

Findings will be classified as package runtime blockers, developer-tooling
limitations, dependency-resolution limitations, or test-fixture assumptions.
Tooling need not itself run on R 3.6 when it can drive an isolated R 3.6
worker; installed package code and its declared runtime closure must.

## 3. Native and build design

The preferred implementation order is:

1. make the package's actual language subset portable to the compiler mode
   supplied by R 3.6 if this requires no loss of clarity, diagnostics, or
   optimization;
2. otherwise select the required standard with a small portable build-system
   gate that works for Unix and Windows without overriding user compiler
   choices;
3. extend the existing `r_api_compat` facade for APIs whose public spelling
   changed after R 3.6;
4. retain the exact current-runtime branch byte-for-byte where practical and
   verify its generated DSO/API inventory and representative hot paths.

Compatibility helpers must express capabilities by the R headers'
`R_VERSION`, use official public compatibility spellings where documented,
and keep API-spelling preprocessor branches at the facade boundary. Narrow
graph capability gates may select which inert edges exist on a runtime. A
shared helper may expose
one version-independent operation to all callers; copying whole validators,
graph walkers, table materializers, or migration engines is prohibited.

## 4. Reproducible R 3.6 environment

The repository will gain an authenticated R 3.6.3 runtime axis with:

- a repository-local runtime prefix or immutable local container input;
- a pinned source/header identity and complete receipt;
- an isolated, pinned package library compatible with R 3.6;
- repository-local HOME, temporary, cache, compiler, and R library state;
- one idempotent bootstrap/verify path and activation support;
- no writes to the host R installation, user library, HOME, or system files.

The dependency solver may use archived source releases for the R 3.6 axis.
That closure is separate from the current development library and must still
satisfy Paradox's public dependency requirements.  Developer-only packages may
be versioned separately or tests may be driven by a current-R coordinator.
The lock records URLs, versions, and hashes so the result does not depend on
the current CRAN index.

Before downloading or building large artifacts, record filesystem and local
container-storage usage and estimate required headroom.  Cleanup is permitted
only if necessary and only from an explicit manifest of ignored,
repository-owned, reproducible cache/image artifacts.  Each candidate path or
image ID is printed and validated before a literal, quoted deletion command;
there will be no wildcard, empty-variable, prefix, recursive repository-root,
or global Podman prune operation.

## 5. Harness changes

The existing API and runtime matrices will add:

- R 3.6.0 headers to the strict compilation/API-token matrix;
- a real R 3.6.3 build/install/test worker;
- version-aware expected DSO symbol inventories for the centralized API
  exceptions;
- a shared source-derived skip/exclusion preflight;
- receipt verification for runtime, dependency lock, package source, loaded
  DSO, tests, logs, and final status;
- a focused development selector and a later release-complete selector.

Independent runtime workers may run in parallel under the existing
memory-aware coordinator, while compilation, BLAS/OpenMP, and testthat
parallelism remain one inside each worker.  The scheduler's aggregate
containment and reserve remain authoritative.  The R 3.6 worker is built once
per exact key and reused; package installations are rebuilt only when package
or compiler inputs change.

## 6. Tests and evidence

Implementation-time gates, in increasing cost order:

1. static raw-token/API inventory and strict compilation against R 3.6.0 and
   every registered API-transition/current header (R 4.0.0, 4.2.0, 4.3.0,
   4.4.0, 4.5.2, and 4.6.1);
2. clean R 3.6.3 package install and registered-routine/direct-probe audit;
3. focused tests for every version-gated helper plus constructors, values,
   dependencies, Conditions, Domains, data-table facades, ALTREP, samplers,
   serialization/current objects, legacy migration, and corruption rejection;
4. the same focused selection on current R, with result normalization only for
   genuinely version-dependent presentation;
5. strict GCC and Clang current-R builds and a source review of every
   compatibility branch;
6. bounded representative performance controls proving the current fast path
   did not regress.

After source convergence, the release matrix will add the complete Paradox
suite and clean source-package check on R 3.6.3 to the already required
runtimes, analyzers, downstream packages, hosted platforms, and release
benchmarks.  This implementation turn may run the complete package suite on
the new oldest runtime when it is the most information-efficient correctness
gate, but it will not launch the complete downstream/memory/documentation
release matrix before the remaining review phase.

## 7. Completion criteria

The change is complete when:

- `DESCRIPTION` declares `R >= 3.6.0`;
- clean source compiles against R 3.6.0 headers and installs/runs on R 3.6.3;
- every compatibility exception is necessary, narrow, documented, version
  audited, and exercised;
- focused old/current runtime results agree on all version-independent
  behavior;
- current-runtime strict builds and representative hot-path controls show no
  material regression;
- the reusable harness can bootstrap, verify, activate, and schedule the new
  axis without host mutation or unsafe cleanup;
- `AGENTS.md`, architecture/compatibility/release documents, `NEWS.md`, and
  operator documentation consistently describe the R 3.6 contract and the
  retained evidence.

All observations and deviations from this plan will be recorded in a final
results ledger here before the implementation is declared complete.

## 8. Selected implementation

The audit selected portable C99; shipped source uses no C11/C17-only language
feature, so the temporary removal of `USE_C17` lost neither optimization nor
clarity. The final release amendment restores `USE_C17` solely as an ordinary
installation ceiling: current R selects its no-later-than-C17 compiler
configuration, while every strict portability lane routes that selected slot
back through GNU C99. R 3.6 may ignore the marker. The semantic implementation
remains single:

- public raw/complex element setters and `IDENT_USE_CLOENV` stay on the current
  headers' inline path; R 3.6--4.1 use public direct access to genuinely fresh
  ordinary destinations and the documented default flag value;
- graph-path indices use bounded decimal arithmetic, and the remaining
  diagnostic-only long-vector positions use exact `%.0f` formatting after
  conversion to double (R's long-vector limit is 2^52). Shipped native source
  therefore has no `%lld`, `%I64`, or `j`/`z`/`t` integer-length format
  dependency, which old Windows R toolchains did not guarantee. The strict
  header gate enforces this source policy, including flags, widths, precision,
  and positional forms. GCC diagnostic pragmas are gated by compiler version
  so old cluster compilers do not warn merely while including R headers.
  Recent R headers can also expose a fixed-base enum, and R >= 4.3 exposes the
  anonymous `Rcomplex` struct as compiler extensions under the package's C99
  mode; the narrow push/pop in `src/paradox.h` suppresses only those
  external-header diagnostics and contains the explicit public
  `R_ext/Complex.h` include used by Paradox, leaving the same pedantic
  diagnostics fatal in package code;
- collection parameter reads now feed the already admitted, rooted core to the
  shared params loader. This removes a temporary environment allocation,
  redundant capsule lookup, and the need for `R_NewEnv()`;
- cold optional binding existence on R 3.6--4.1 uses
  `base::exists(..., inherits = FALSE)`. Candidate-shell and fresh-destination
  classifiers use that absence-tolerant path; admitted capsule and generation
  reads retain the required native path, avoiding an R evaluation on every old-
  runtime hot operation. Required authenticated ordinary-frame binding
  snapshots remain allocation-free. The terminal genuine-shell optional
  receipt scan cannot allocate, so it
  uses old-only, ledgered `R_HasFancyBindings()` to reject a fancy frame before
  the stored-cell scan. `UserDefinedDatabase` environments are rejected by
  R's public inheritance predicate before every facade operation because their
  callback-backed table is outside the ordinary-frame contract and the old
  fancy-binding helper assumes an incompatible hash-table layout. The graph
  boundary precedes namespace/package classification because those predicates
  perform an object-table lookup on old R;
- capsule graph-path frames no longer treat raw `R_alloc()` storage as a GC
  root. One managed carrier owns each active shell and its exact selected core
  generation across optional lookup, evaluator/finalizer reentry, deep-stack
  growth, and child extraction. It is shared by all runtime branches, clears
  carrier slots on pop, and retains the 16-frame native inline common path. A
  compile-time-only strict probe detaches every core in a 21-node path and
  forces GC/pending finalizers; the ordinary suite independently exercises the
  same depth under `gctorture()`;
- a pre-4.6 required snapshot authenticates its binding once, then calls the
  centralized stored-cell selector directly. It no longer repeats the same
  class/active-binding boundary immediately before a selector that cannot
  allocate or dispatch on the admitted ordinary frame;
- the R 3.6--4.1 ownership gateway rejects a non-object `self` through its
  constant-time object bit before the required reader can encounter an absent
  R6 enclosure binding. This diagnostic guard is compiled out from R 4.2,
  where the public binding-existence API already handles absence, and does not
  add work to the current hot path;
- `Rf_findVarInFrame` remains confined to R < 4.6, while
  `R_PromiseExpr`, `PRENV`, and `PRVALUE` are confined to R < 4.5 because
  R 4.5 compiled-code policy already classifies them as non-API. R 4.5 fails
  recursive migration closed on reached promises. Ordinary factory callback
  closures can retain formal promises in their lexical frame even when the
  formal was forced or is not referenced, so this limitation can surface
  without explicit `delayedAssign()`. Users perform that one-way migration
  under R 4.0--4.4 or R >= 4.6; ordinary Paradox operations on R 4.5 remain
  supported. R >= 4.6 retains its public binding/dots APIs;
- `R_getVar` is public in R 4.5 but is forbidden in every pre-4.6 DSO because
  it can force a delayed binding without the classifier added in R 4.6. The
  current source contains three reviewed call sites and every call follows
  `R_GetBindingType` after direct/forced-value classification; the DSO
  contains one undefined-symbol row;
- simple Domain IDs use the same bounded native renderer on all supported
  runtimes. Its only versioned operation is the `scipen` snapshot: R >= 4.5
  uses documented `Rf_GetOption1`, while R 3.6--4.4 evaluates public
  `base::getOption()` inside the compatibility facade. This avoids both an
  old-R policy exception and the former unconditional `deparse1()` fallback.
  The DSO gate forbids `Rf_GetOption1` on R 3.6/4.0/4.3 and requires it exactly
  once on R 4.5/current. Unsupported or unstable representations still use the
  shared R fallback for correctness;
- the exact R 4.5.2 runtime stage runs `tools:::check_compiled_code()` on the
  installed package and retains a manifest-bound zero-issue receipt, so R's own
  policy list remains authoritative in addition to the explicit DSO inventory;
- R 3.6 has no accessor for an active-binding function. Direct and recursive
  legacy ParamSet-family migration fail closed when its inspection is required
  and request R >= 4.0. Because Paradox-1 ParamSet-family R6 shells themselves
  contain active bindings, their practical object/graph migration requires
  R >= 4.0. Exact built-in current Paradox-2 shells use a narrow authenticated
  capsule traversal on R 3.6; locked methods are omitted but unlocked
  replacement closures remain graph edges. Package active facades and relocked
  method replacements are opaque because unsupported replacements cannot be
  distinguished when every receipt available on that runtime is preserved;
  such a closure is not traversed, and an active binding is never invoked.
  Additive shells and modifications that
  prevent exact authentication fail closed. Current operations,
  idempotent current-object conversion, standalone legacy Domain/Condition
  conversion, and graphs without arbitrary active bindings remain supported
  on R 3.6;
- R before 4.3 cannot construct list ALTREP. Only the adversarial VECSXP ALTREP
  fixture is version-gated; atomic ALTREP remains tested and the production
  list-ALTREP branch is vacuous on those runtimes.
- imports environments are authenticated through public structure rather than
  printable metadata: the raw ordinary scalar `name` must begin `imports:`
  and the direct parent must be `R_BaseNamespace`. A user environment that
  merely spoofs the prefix remains traversable. This fixes a silent
  recursive-upgrade omission and removes the old `environmentName()` call from
  that boundary.

The runtime design uses the checked-in `environment/runtime-matrix.tsv`
registry and exact conda prefix locks for R 3.6.3 and every R 4 minor from
4.0.5 through 4.5.2. R 3.6.3 through R 4.2.3 additionally use separate
authenticated source-package library locks. The real R 4.0.5 and R 4.1.3
axes cover active-binding inspection together with the pre-R-4.2
compatibility branch, and R 4.2.3 begins the next public-API combination,
instead of inferring those combinations from header-only compilation. The API
matrix begins with R 3.6.0 headers;
4.0.0 and 4.2.0 axes cover the active-binding and binding-existence/element-
setter transitions. Final commands, identities, and outcomes are recorded in
the results ledger below.

Bootstrap owns every persistent dependency-library mutation. Selecting
R 3.6.3 in provisioning mode provisions both its complete-test closure and
its separate declared-floor closure; `--verify` verifies both read-only, and
the source-bound coordinator never repairs or provisions either cache. Each
stage also replaces activation's live developer startup paths with detached,
authenticated copies of `environment/Renviron`, `environment/Rprofile.R`, and
`environment/Makevars` before its first build or R process. This includes the
command-specific `R_BUILD_ENVIRON`, `R_CHECK_ENVIRON`, and
`R_INSTALL_ENVIRON` selectors, not only ordinary R startup. Thus neither a
missing floor receipt nor a concurrent checkout edit can change an admitted
candidate run.

The R 3.6 stage now owns an independent exact-floor proof without duplicating
its complete suite. The shared sealed library manager has a
`declared-floor` profile containing backports 1.1.7, checkmate 2.0.0,
data.table 1.18.4, mlr3misc 0.10.0, R6 2.6.1, and the sole transitive
dependency digest 0.6.39. The exact lock SHA-256 is
`bee16543027ea2bec1d905d32bf9b9a6ae893371778c254166df4353a1229975`.
It is built once from SHA-256-authenticated source,
then handed to every selected R 3.6 stage by receipt. The already-built
candidate tarball is installed into a fresh candidate-only library. That
directory is created and authenticated before the stage closes its pinned
artifact-root descriptor; the descriptor is closed before any build or R
child, and no later path helper may assume it remains live. A bounded
smoke authenticates every installed package identity and dependency namespace
origin, plus the candidate Paradox DLL origin and registration, and exercises
representative deparse, check, dormant dependency, diagnostic, grid,
data.table, mlr3misc, and R6 paths. Ambient `R_DEFAULT_PACKAGES` is removed so
the proof is independent of operator startup settings.

A complete seven-runtime run also has one cross-version serialization gate
after all individual stages are sealed. Exact R 4.0.5 produces a current-v2
nested BASE/COLLECTION/SHADOW graph, and exact R 3.6.3 loads, exercises,
mutates, and reserializes it. The fixture covers shared topology, an
attribute-hidden closure, dormant and named-`NULL` values, callbacks,
transformations, checks, and capsule mutation. The exact stage package/DSO
paths, fixture/round-trip bytes, receipts, logs, semantic results, and isolated
state are sealed and replayed. Partial runtime selections explicitly retain
no cross-runtime claim.

The runtime-prefix boundary was strengthened after the final header gate
caught one sysroot inode shared by micromamba's extracted package cache and
all four sealed prefixes. One in-place write had therefore invalidated every
content receipt at once. Fresh prefixes use `--always-copy`; receipt creation
and verification reject all multiply-linked regular files. Old linked
prefixes are deliberately reprovisioned from the exact locks rather than
deleted automatically or blessed with refreshed manifests.

The current-R full native gate likewise no longer lets reticulate or uv
resolve its ConfigSpace dependencies. `scripts/bootstrap-configspace`
provisions two exact, copied Python 3.10.20 prefixes—ConfigSpace 1.2.2 and
0.5.0—from checked-in SHA-256 `@EXPLICIT` locks, seals their ordinary
filesystem state, and records authenticated receipts. The gate consumes
`.local/configspace` read-only and networkless, selects both interpreters by
exact path, and verifies the locks, inventories, manifests, receipts, and
write protection before and after testing. Incomplete state is preserved for
manual review and exact-path removal rather than auto-deleted. This is a
current-R full-test dependency fixture; it does not add reticulate or
ConfigSpace to the R 3.6 runtime closure.

The local R 3.6.3 source-package check runs with forced Suggests disabled after
the complete supported suite has already run from source. Its authenticated
test lock contains five direct Suggests and omits exactly `reticulate`,
`rmarkdown`, `mlr3learners`, and `e1071`. This lane therefore requires child
exit zero, exactly that one missing-Suggests dependency NOTE, no other
NOTE/WARNING/ERROR/halt, and one sole final `Status: 1 NOTE`; it must not claim
an impossible `Status: OK`. R 3.6's Unix checker hard-codes
`Sys.which("nm")` rather than consulting the activated `NM`. The runtime
prefix already contains the matching target-tool alias under
`$CONDA_TOOLCHAIN_HOST/bin/nm`, bound by the complete prefix receipt. The
stage verifies its exact relative target and resolved inode, then prepends
that directory only for this check. This avoids both a machine-dependent host
`nm` and a worker-global or copied duplicate of the compiler tool.

The hosted portability design adds one independent Windows x86-64 job pinned
to exact R 3.6.3 and Rtools35 GCC 4.9.3. It is deliberately not another full
old-R behavior runner. A reviewed PowerShell driver installs only the seven
runtime packages selected from
